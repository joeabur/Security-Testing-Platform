# SEO: public landing page, sitemap, and Search Console

This platform is almost entirely an authenticated app — dashboard,
organizations, targets, findings, all behind login. The only page meant for
search engines and anonymous visitors is the root marketing page,
`frontend/app/page.tsx`. Everything below is scoped to that one page.

## What's implemented

- **`frontend/app/page.tsx`** — a public landing page (replacing the old
  unconditional redirect to `/login`/`/dashboard`) targeting the keyword
  theme "AI security testing" / "AI red teaming", with copy covering
  generative AI risk assessment, LLM red teaming, and the AppSec/repository
  scanning capabilities. An already-authenticated visitor is still
  redirected straight to `/dashboard`.
- **`frontend/app/layout.tsx`** — added `metadataBase` so relative Open
  Graph/canonical URLs resolve correctly.
- **`frontend/app/page.tsx`** metadata — title, meta description, keywords,
  canonical URL, Open Graph and Twitter card tags, plus a `SoftwareApplication`
  JSON-LD block.
- **`frontend/app/sitemap.ts`** — Next.js's App Router sitemap convention;
  served at `/sitemap.xml`. Lists only the public landing page — every other
  route is behind auth and would just have crawlers hit a login redirect.
- **`frontend/public/robots.txt`** — now allows `/` (exact match only) and
  explicitly disallows `/login`, `/register`, `/dashboard`, `/organizations`,
  and (as a catch-all) everything else, plus a `Sitemap:` directive.

## Placeholder domain — swap before deploying

There is no production domain yet, so every absolute URL uses the
placeholder `https://YOUR-DOMAIN.com`. Before deploying, find-and-replace it
in:

- `frontend/app/layout.tsx` (`SITE_URL` / `metadataBase`)
- `frontend/app/page.tsx` (`SITE_URL`, used in canonical + Open Graph `url`)
- `frontend/app/sitemap.ts` (`SITE_URL`)
- `frontend/public/robots.txt` (`Sitemap:` line)

```
grep -rl 'YOUR-DOMAIN.com' frontend/
```

is the check that everything has been swapped.

## Submitting to Google Search Console (manual — needs your Google account)

I don't have browser or Google-account access in this session, so I can't
click through Search Console myself. Once the real domain is live:

1. **Verify domain ownership.**
   - Go to https://search.google.com/search-console, "Add property", enter
     the real domain.
   - Easiest method given this is a Next.js app: the **HTML file** method.
     Search Console gives you a file named like
     `google1234567890abcdef.html` — download it and drop it directly into
     `frontend/public/` (it's a static file, served as-is at
     `https://YOUR-DOMAIN.com/google1234567890abcdef.html`). Deploy, then
     click "Verify" in Search Console.
   - Alternative: the **DNS TXT record** method works just as well if you
     manage DNS for the domain and would rather not add a file to the repo.
2. **Submit the sitemap.**
   - In Search Console, left nav → "Sitemaps".
   - Enter `sitemap.xml` (resolves to `https://YOUR-DOMAIN.com/sitemap.xml`,
     generated by `frontend/app/sitemap.ts`) and click "Submit".
3. **Request indexing for the landing page** (optional, speeds up first
   crawl).
   - "URL Inspection" → paste the root URL → "Request indexing".

None of this can happen before the domain swap above and a real deployment
— Search Console can't verify or crawl a placeholder domain.

## Keyword targeting

The landing page's `<h1>`, meta description, and body copy target: "AI
security testing", "AI red teaming", "generative AI risk assessment", "LLM
security testing", and related terms. If you want to target a narrower
phrase instead (e.g. a specific product category or competitor comparison
term), update `frontend/app/page.tsx`'s `TITLE`, `DESCRIPTION`, `keywords`,
and the `<h1>`/hero copy together — they should all say the same thing for
a search engine to treat the page as authoritative for that phrase.
